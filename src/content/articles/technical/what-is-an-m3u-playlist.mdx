An M3U playlist is a text file that lists media addresses, one after another. The file itself has no video in it: a player reads an address, then fetches the picture from there.

People use the same simple layout for music files and for live channels. IPTV players adopted it because a channel list can be opened, edited and saved without a special database. The catch is that a tiny text mistake stops a channel, and the mistake is invisible until you open the file.

## What an M3U playlist actually is

The format began as a playlist for audio players. A later "extended" form added a line of information before each address, which is why live channel lists look the way they do. Nothing in that history makes the file a video format. Copy the file to another computer and it is still just text. The picture stays on the server named in each address.

That is also why the format spread. A service, a broadcaster app, or a person maintaining a local list can hand over one file instead of clicking through a grid of channels. The player does the fetching. If you are deciding whether you are allowed to fetch a given stream, the filename will not tell you. Read [is IPTV legal?](/legal-streaming/is-iptv-legal/) for that distinction.

<Callout type="note">
Examples on this page use made-up hosts ending in .invalid. They are there to show the shape of the file. They are not addresses you should try to open.
</Callout>

## The anatomy of an M3U file

A typical channel list has a header, then pairs of lines. Here is a minimal example:

```text
#EXTM3U
#EXTINF:-1 tvg-id="ExampleNews" tvg-logo="https://cdn.invalid/logos/news.png" group-title="News",Example News
https://stream.invalid/live/news/index.m3u8
```

Read it from the top. `#EXTM3U` says "this is an extended playlist". The next line is metadata for one channel. The line after that is the address the player should open. Then the pattern repeats: information, address, information, address.

### The #EXTM3U header

The header should be the first line. Players use it to decide that the following lines are an extended playlist rather than a bare list of paths. If the header is missing, some players still try to read addresses, and others refuse the file. Putting the header on line 1 removes that gamble.

The header can also carry a guide address. You will see attributes such as `url-tvg` or `x-tvg-url` pointing at an XMLTV file. Those names are player conventions, not a single official standard with one spelling. The idea is the same: "here is a guide to download". How a guide file is built is covered in [XMLTV and the EPG](/technical/xmltv-and-epg-explained/).

{/* VERIFY: which header attribute your player actually reads for the guide address */}

```text
#EXTM3U url-tvg="https://cdn.invalid/guide.xml"
```

If the guide address is wrong, the channels can still play. Only the programme grid fails. That split is useful. Picture without a guide means the stream addresses are fine and the guide link, or the ids inside it, is not.

### #EXTINF lines and their attributes

`#EXTINF` is the information line. A common shape is:

```text
#EXTINF:-1 tvg-id="ExampleNews" tvg-name="Example News" tvg-logo="https://cdn.invalid/logos/news.png" group-title="News",Example News
```

The `-1` is a duration in seconds. For a music track it would be the length of the song. For a live channel there is no fixed length, so lists use `-1` to mean "keep going". A positive number does not turn a live channel into a recording. It is only a hint some players ignore.

Attributes sit between the duration and the comma. They are usually written as `name="value"`.

| Attribute | Role |
| --- | --- |
| tvg-id | String the player matches to a guide channel. Spelling and case matter. |
| tvg-name | Optional name some players prefer over the text after the comma. |
| tvg-logo | Address of an icon. A broken icon does not stop playback. |
| group-title | Folder or group name in the channel list. |

The display name is the text after the comma. In the example, the viewer sees "Example News". The comma is not decoration. If it is missing, the player can swallow the attributes into the name, or drop the name entirely.

Quote the values. A group called News and Sport needs quotes so the space does not end the attribute early: `group-title="News and Sport"`. An unquoted space is a classic reason a whole group disappears or merges into the next field.

Other attributes show up in real files: catch-up hints, language tags, and names only one vendor's player understands. Treat unknown attributes as optional. A player that does not recognise one should still play the address on the following line. Do not add attributes from a forum post unless you know that your player documents them.

### Stream URLs and formats

The address line is whatever the player should open. Three patterns are common, and they are not interchangeable just because they all appear in a playlist.

HLS addresses often end in `.m3u8`. [RFC 8216](https://www.rfc-editor.org/rfc/rfc8216) specifies that kind of playlist: it lists media segments, or points at variant playlists of different quality. The player downloads segments in order. That is different from a channel list, even when both files use the same extension.

MPEG transport stream addresses often end in `.ts` or have no familiar ending and are opened as a continuous stream. The player reads a flow of packets rather than a list of segments.

DASH manifests often end in `.mpd`. They describe representations and segments in XML. A player that only understands HLS will not play a DASH address, and the failure can look like a dead channel rather than a format mismatch.

The playlist does not convert between these. It only stores the address. If one channel plays and the next shows a black screen, compare the address endings before you reinstall the player.

## M3U vs M3U8

The extra "8" is doing two jobs in the wild, and mixing them up causes bad advice.

First, encoding. A file named `.m3u` is sometimes saved in an older encoding that cannot represent every channel name. `.m3u8` signals UTF-8, so names in Arabic, Cyrillic, or accented Latin survive. If names look like random symbols, reopen the file as UTF-8 and save it as UTF-8 without adding a byte-order mark at the start. A BOM is invisible in some editors and is enough to make the header look wrong to a strict player.

Second, HLS. A segment playlist is also called a media playlist and commonly uses `.m3u8`. Open it and you will see tags such as `#EXTINF` with a short duration, then a segment file, repeated many times, often with `#EXT-X-TARGETDURATION` nearby. That file describes one stream chopped into pieces. It is not a list of television channels. Pointing a "load playlist" button at a single HLS media playlist can load one stream, or nothing, depending on the player. Pointing it at a channel list loads many channels.

<Callout type="tip">
If the file has hundreds of short segment names, it is an HLS media playlist. If it has channel names and long-lived addresses, it is a channel list. The extension alone is not the test.
</Callout>

## How players use tvg-id to match an EPG

The guide, or EPG, is a separate file. XMLTV is the format most of these players expect. In that format a channel has an id, and each programme points at that same id. The picture playlist is a third thing. The player joins them by string match: the `tvg-id` value should be the same string as the guide's channel id.

If the guide says `example.news` and the playlist says `ExampleNews`, a player that compares those strings exactly will leave the guide blank for a channel that otherwise plays. Renaming the on-screen title does not fix that. The id does.

Some players fall back to the display name when the id is empty. That fallback is a feature of the player, not of the file format. Check it on the player you use before you delete ids to "simplify" a file.

## Validating a playlist

You can check a file with a text editor. You do not need the television for the first pass.

<ScreenshotSlot id="m3u-text-editor" device="Desktop computer" what="A short example playlist with made-up .invalid addresses open in a text editor, showing the header and one channel entry" />

<Steps>
<Step title="Confirm the encoding">
Save as UTF-8 without a BOM. If an editor offers "UTF-8 with BOM", choose the one without it and save again.
</Step>
<Step title="Check line endings once">
Use either Unix line endings or Windows line endings for the whole file. Mixing them is a rare but real way for a blank-looking line to appear.
</Step>
<Step title="Pair every information line with an address">
The address is the next line. No blank line between them. No second address before the next `#EXTINF`.
<Result>
If a channel is missing in the player but present in the file, this pairing is the first place to look. A visual gap in the editor is the usual find.
</Result>
</Step>
<Step title="Check quotes and the comma">
Every attribute value that contains a space is quoted. Exactly one comma separates the attributes from the display name.
</Step>
<Step title="Remove trailing spaces">
A space at the end of an address can make the request fail. It will not show up in a casual glance.
</Step>
</Steps>

A desktop player is a convenient second opinion because you can edit, save, and reload quickly. Pass that test before you copy the file to a television stick. Loading the same file on a Fire TV Stick is covered in [how to set up an IPTV player on Fire TV Stick](/setup/iptv-on-firestick/). If it loads on the desktop and not on the stick, suspect memory, a trimmed copy, or a different guide address, not the basic syntax you already checked.

Also scan for addresses that are clearly cut off: a line that stops at `https://` or a quote that never closes. Those entries will sit in the list and fail when selected, which feels like buffering. It is a broken line.

One last structural check is worth doing before you leave the editor. Count `#EXTINF` lines and count address lines. The two counts should match, and the header should not be part of either count. If you have more information lines than addresses, a channel was left unfinished. If you have more addresses than information lines, a bare path is sitting in the file and some players will show it as a nameless entry or skip it. That count takes a minute and catches the mistakes a visual skim misses, especially in a long list where one broken pair hides among hundreds of healthy ones.

## Legal note

The format is neutral. A text file can point at a broadcast you are allowed to watch, or at a stream nobody licensed. The extension does not make either one lawful.
